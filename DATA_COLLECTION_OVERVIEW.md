# Data Collection & Methodology Overview - Accident Alert App

The Accident Alert App employs a comprehensive data collection and feature engineering methodology to detect vehicle accidents in real-time using edge AI. The system processes vehicle motion sensor data collected at high frequency, applies intelligent preprocessing and feature extraction, and trains a machine learning model to distinguish between real traffic accidents and false alarms. The foundation of the Accident Alert App's accident detection system is built upon vehicle motion sensor data comprising 3,084 samples collected from real-world driving scenarios and controlled impact simulations. The data collection leverages the smartphone's built-in accelerometer and gyroscope sensors, which operate as a 6-axis motion sensing system. The accelerometer captures three-dimensional linear acceleration data, while the gyroscope measures rotational velocities around three axes. These sensors operate at a high sampling rate of 100 Hz, meaning 100 observations are collected every second, providing granular temporal resolution critical for detecting the rapid dynamics of vehicle collisions. The collection window is set to a 2-second sliding buffer, which captures exactly 200 samples per sensor during this period. This window size represents an optimal trade-off: long enough to capture the full dynamics of a collision event (which typically lasts 100-500 milliseconds), yet short enough to provide near-real-time responsiveness for emergency alerting. The entire dataset encompasses diverse driving scenarios including normal acceleration, braking, sharp turns, speed bumps, as well as various collision types such as front-end impacts, side collisions, and rollover events, ensuring the model learns to recognize accidents across different severity levels and impact angles.

The raw dataset consists of sensor readings organized into a structured format with six primary sensor inputs and class labels for supervised learning. Each record contains three accelerometer readings (AccX, AccY, AccZ) representing lateral, forward/backward, and vertical acceleration respectively, along with three gyroscope readings (GyroX, GyroY, GyroZ) capturing rotation velocities around the same three axes. Additionally, each record includes a timestamp and a class label indicating the driving scenario. The dataset exhibits a class distribution of AGGRESSIVE scenarios (38.9%), which represent actual or simulated collision events, versus NORMAL and SLOW driving patterns (61.1%), which represent false alarm scenarios including routine acceleration, deceleration, sharp turns, and road obstacles. This class distribution reflects real-world prevalence where normal driving far exceeds actual accidents, creating a natural imbalance challenge that the preprocessing pipeline must handle. Sample records from the dataset demonstrate clear distinctions between collision patterns and normal driving: genuine impacts show sudden, high-magnitude acceleration spikes across multiple axes combined with significant rotational motion, while normal driving exhibits gradual, low-magnitude changes with minimal rotation. The raw data serves as the input to the preprocessing pipeline, which transforms these six sensor values into 19 engineered features optimized for accident detection.

The preprocessing pipeline transforms raw sensor data into machine learning-ready datasets through a systematic four-step process: loading, engineering, validating, and splitting. In the loading phase, the raw sensor data is read from the combined_dataset.csv file and verified for completeness and integrity. The engineering phase is where the pipeline creates 19 engineered features from the 6 raw sensor inputs through mathematical transformations that capture both immediate impact signatures and temporal patterns of accident events. During validation, the pipeline removes records with missing values, filters out anomalies or invalid readings, and ensures timestamp sequences are logical and continuous. Finally, the splitting phase divides the comprehensive dataset into three separate datasets using a 70% training, 15% testing, and 15% validation split, ensuring proper model evaluation methodology. The training dataset contains 2,159 samples used to teach the machine learning model to recognize accident patterns, the testing dataset contains 462 samples used to evaluate model performance on unseen data, and the validation dataset contains 463 samples providing an additional independent check of model generalization. This produces three processed CSV files (training_data.csv, test_data.csv, validation_data.csv) containing all 19 engineered features plus the class labels, which serve as input to the model training process and enable reproducible, rigorous model evaluation.

The feature engineering process is the critical bridge between raw sensor readings and machine learning-ready features, transforming 6 dimensional sensor data into a 19-dimensional feature space that captures the multi-faceted signatures of vehicle collisions. The feature set is organized into five logical categories, each targeting different aspects of accident detection. The impact features (4 features) include the magnitude of total acceleration computed from the three-axis accelerometer readings, along with the individual X, Y, and Z components. These impact features directly measure the force of a collision, which is the most obvious and important indicator of an accident. The speed features (3 features) capture the temporal dynamics of a collision by computing the vehicle's estimated speed before the impact, the speed after the impact, and the rate of change or deceleration between these two states. These speed features are critical because real collisions are characterized by sudden, significant deceleration, whereas normal driving involves gradual speed changes. The rotation features (4 features) measure rotational motion around all three axes using the gyroscope data, plus a composite magnitude metric capturing total rotational velocity. These features indicate the vehicle's orientation changes and tumbling behavior, which differ dramatically between controlled turning maneuvers and uncontrolled collision responses. The duration features (2 features) capture temporal characteristics: the impact duration measures how long the high-acceleration event persists, while secondary impacts counts the number of distinct collision peaks that may occur as different car parts strike objects sequentially. Real accidents typically exhibit longer impact durations and multiple peaks, distinguishing them from momentary vibrations or road obstacles. Finally, the context features (6 features) include immobility duration measuring post-collision vehicle stillness, altitude changes from GPS data indicating elevation variations on roads, GPS accuracy reflecting location precision, time of day providing temporal context, a binary indicator of whether the vehicle is moving, and post-vibration measurements capturing sustained shaking after an impact. Together, these 19 features create a rich representation of accident events that enables the machine learning model to distinguish genuine collisions from false alarms with high accuracy and confidence.

The data flows through a well-defined pathway from initial collection through final model training. Raw sensor data is continuously collected from smartphone accelerometer and gyroscope sensors at 100 Hz frequency. Every 2 seconds, the sliding window buffer accumulates 200 samples which are then processed through the preprocessing pipeline. The pipeline computes all 19 engineered features from the raw sensor values, validates data quality, and assigns class labels based on the driving scenario type (AGGRESSIVE or NORMAL/SLOW). After preprocessing, the complete dataset of 3,084 records with 19 features each is split into training (70%), testing (15%), and validation (15%) subsets. These processed datasets are saved as CSV files and fed into the model training process. The Random Forest classifier is then trained on the training dataset, evaluated on the testing dataset, and finally validated on the independent validation dataset. This rigorous pipeline ensures that the machine learning model receives clean, well-engineered features and that model performance is evaluated fairly on data the model has never seen during training. The preprocessing pipeline implements multiple data quality checks to ensure reliable features for model training. Missing value detection identifies and handles incomplete records. Outlier filtering removes sensor readings that deviate excessively from expected physical ranges. Timestamp validation ensures temporal continuity and identifies gaps or duplicate timestamps. Sensor calibration verification confirms that gravity is properly accounted for in accelerometer readings. Feature range validation checks that all engineered features fall within expected physical bounds, alerting to computation errors. Class balance analysis confirms the distribution of accident versus non-accident samples. These quality assurance measures protect the integrity of the training data and ensure that the machine learning model learns meaningful patterns rather than artifacts or errors.

The preprocessing pipeline is implemented in the Python script `preprocess_data.py` located in the `accident_alert_app/datasets/` directory. This script automates the entire data transformation process: reading raw CSV data, computing 19 engineered features, validating data quality, splitting into train/test/validation sets, and saving three processed CSV files. The script uses pandas for data manipulation, NumPy for numerical computations, and includes detailed logging of the preprocessing steps for transparency and debugging. The modular design allows for easy modifications to feature engineering logic or data splitting ratios. Upon completion, the script generates feature statistics and summaries, including descriptive statistics for each engineered feature and the class distribution in each dataset split. This reproducible, documented preprocessing ensures consistency and enables easy replication or modification of the data preparation process. The underlying sensor data originates from the Kaggle Driving Behavior Dataset by outofskills, which is freely available under open data license. This real-world driving behavior dataset containing 3,084 sensor samples has been processed and engineered into 19 features to power the accident detection machine learning model. The dataset was created by outofskills and is available on Kaggle (www.kaggle.com) at https://www.kaggle.com/datasets/outofskills/driving-behavior under an open data license, making it freely accessible for research and development purposes.

Once the data has been preprocessed and split into training, testing, and validation sets, the datasets are fed into the machine learning model training framework. The Random Forest classifier ingests the 19 engineered features as input and the class labels (REAL accident vs FAKE alarm) as output, learning to map feature patterns to accident classifications. Model hyperparameters are configured to handle class imbalance and prevent overfitting. The trained model is evaluated on the test set to estimate generalization performance, and further validated on the independent validation set. Feature importance analysis reveals which engineered features contribute most to accurate predictions. The trained model is then packaged for mobile deployment, typically by converting from Python pickle format to JSON format for easier integration into the Flutter mobile application. The three-layer detection system (shake filter, ML classifier, confidence threshold) is then integrated into the app's real-time processing pipeline, enabling on-device accident detection with millisecond-level response times and full privacy preservation. In summary, the data collection begins with 3,084 vehicle motion sensor samples collected at 100 Hz over 2-second windows, providing 6 raw sensor dimensions (AccX, AccY, AccZ, GyroX, GyroY, GyroZ) with class distribution of AGGRESSIVE (38.9%) and NORMAL/SLOW (61.1%). The preprocessing pipeline loads this data, engineers 19 features organized into impact (4), speed (3), rotation (4), duration (2), and context (6) categories, validates quality, and splits into training (2,159 samples, 70%), testing (462 samples, 15%), and validation (463 samples, 15%) datasets. These preprocessing steps are implemented in the Python script `preprocess_data.py` and produce three CSV files containing all 19 engineered features that become input to the Random Forest machine learning model, which ultimately powers the three-layer accident detection system deployed on mobile devices for real-time, privacy-preserving emergency response.
